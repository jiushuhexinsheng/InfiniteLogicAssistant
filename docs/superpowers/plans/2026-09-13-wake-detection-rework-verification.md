## 为什么这 6 项不能由自动化代替

重构期间所有实测用的都是 **SAPI 合成音**（Windows 语音合成），而不是真人说话：

| 说的 | 云端 ASR 听成 | 结论 |
|---|---|---|
| 洛吉斯 | `洛吉斯。` | 一字不差 |
| 衍衡 | `燕恒。` | 差一个同音字（已由同音字表覆盖）|

**合成音清晰、语速均匀，真人不是。** 云端对合成音识别好，**不代表对真人好** —— 而整个方案成立与否就取决于这一点。所以下面 6 项是硬门槛：**不通过就不算完成**，且**不得在未实际执行的情况下填写结果**。

## 前置

```bash
python main.py serve        # 后端 + 前端（web/dist），默认 http://127.0.0.1:8520
```

浏览器打开 → 点悬浮球上的 **mic 徽章**开启唤醒（或页面上的「开启语音唤醒」）。
确认麦克风与扬声器可用、**音量不为静音**。

## 验收项

| # | 说 / 做 | 预期 | 结果 |
|---|---|---|---|
| 1 | 「衍衡，帮我查天气」 | 一句话直接起任务，**不等提示音**（唤醒词与指令由 VAD 切成一段） | ☐ |
| 2 | 「衍衡」→ 听提示音 → 「现在几点」 | 两步走通（唤醒词单独一段 → 提示音 → 命令单独一段） | ☐ |
| 3 | 「洛吉斯，现在几点」 | 第二个唤醒词同样可用 | ☐ |
| 4 | 「衍衡」→ 不说话 | 不产生任务、不报错；等指令窗口过期后回到聆听 | ☐ |
| 5 | 屋里正常聊天（**不含唤醒词**） | **不误触发** | ☐ |
| 6 | 双击悬浮球 | 手动触发仍可用（回归；唤醒词之外的独立入口） | ☐ |

**第 5 项最要紧**：误唤醒是本方案最大的风险（VAD 会把任何疑似人声送去云端转写），而它只有真人能验。

## 自动化辅助（可选用）

脚本负责搭场景、采证据、判客观项；人只负责出声与听声：

```bash
cd web && npm run verify:voice
```

判据来自互相独立的三个信号：状态机的结果（DOM 状态类）、麦克风的实际开合（活轨道数）、浏览器的真实播报标志（`speechSynthesis.speaking`）。

> **它的规矩是「采不到证据就报 INCONCLUSIVE，绝不报 PASS」** —— 一个「什么都没看见所以通过」的检查是假保障，比没有检查更糟。（此原则本身也是本轮修出来的：旧版检查 4 探的是随 Vosk 一起删掉的全局，取值恒为假、FAIL 分支不可达，只能报空洞的 PASS。）

报告写到 `docs/superpowers/plans/voice-verification-report.md`（该文件不入库，结论请回填本表）。
